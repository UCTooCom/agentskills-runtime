## 比赛主题

### Hackathon Idea

**Build a software factory for requirements.**

Participants are expected to build an agent system, not a one-shot generation demo. The workflow breaks a large requirement into modules, delegates work, and keeps verification visible from start to finish.

Build a software factory that compiles large requirements into reliable GitHub-style collaboration and spreadsheet applications.

---

## 任务介绍

### Agentic Software Factory Hackathon Tasks

本次黑客松包含两大任务方向，参赛队伍需构建一个能将大型需求编译为可靠软件的智能体工厂系统。

---

### 任务一：Software Engineering · GitHub-style ERP

A simulated GitHub-style website for software-engineering workflows and ERP-like team operations. Build the collaboration system behind a development organization.

**模块清单：**
- Accounts
- Organizations
- Teams
- Repositories
- Branches
- Issues
- Pull requests
- Permissions

---

### 任务二：Data Workspace · Google Sheets-style

A simulated Google Sheets-style website for data storage, presentation, and processing. Build a persistent workspace where people can organize and analyse tabular information.

**模块清单：**
- Workbooks
- Worksheets
- Cells
- Formulas
- Data operations
- Filters
- Validation
- Pivot summaries

---

## 参赛方式

1. **Upload an agent snapshot or select a built-in one.**
   上传智能体快照，或选择内置智能体。

2. **Compile the large requirement into smaller runnable modules.**
   将大型需求拆解编译为更小的、可运行的模块。

3. **Run the GitHub-style and spreadsheet-style tasks in order.**
   按顺序运行 GitHub 风格任务和电子表格风格任务。

4. **Inspect evidence and refine the system until the output is stable.**
   检查输出证据，迭代优化系统，直至输出稳定可靠。

---

## 竞赛说明

- **Treat the requirement document as the source of truth.**
  以需求文档为唯一真实来源。

- **Keep changes small enough to verify each step.**
  保持每次变更足够小，确保每一步都可验证。

- **Use the task artifacts to explain what your agent changed.**
  使用任务产物来解释智能体做了哪些变更。
