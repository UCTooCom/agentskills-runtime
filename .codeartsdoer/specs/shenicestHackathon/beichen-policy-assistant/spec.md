# **1. 组件定位**

## **1.1 核心职责**

本技能 `beichen-policy-assistant` 是运行在 AgentSkills Runtime 上的一个园区产业服务技能，实现北辰命题"政策赋能精准化"课题要求的**政策库 — 匹配库 — 申报库全流程服务**：

1. **全景企业画像**：输入企业名称，自动采集企业工商、经营、舆情等全域公开信息，经信息甄别、冗余过滤、要点萃取，产出结构化企业画像（对标命题"数据采集层面 + 智能处理层面"）
2. **政策知识库建设**：建设三层知识库——**政策原文库**（收录市、区两级最全最新政策，命题附件提供 74 条政策目录）、**官方解读库**（权威问答与解读，锚定官方口径）、**实操洞察库**（申报实操要点与隐性规则），以高质量数据集根除 AI 幻觉
3. **多元政策匹配**：联动本地政策库与全网实时公开资源双渠道检索，基于企业画像语义匹配（打破关键词局限），自动筛除无效无关信息，输出"企业 → 政策"适配研判报告
4. **政策库自动更新**：每日定时从北京市人民政府、朝阳区人民政府、北京市科委、中关村管委会等官方网站抓取最新产业政策，汇入政策储备库；经人工研判确认后转入政策正式库
5. **申报闭环管理**：对已匹配政策建立申报任务（匹配库 → 申报库），跟踪申报材料、申报进度与结果，形成全流程闭环
6. **结果落库与呈现**：企业画像写入 `company` 表，政策匹配报告与申报任务写入 `tasks` 表，复用 aibuilder 模块呈现

## **1.2 核心输入**

1. **企业名称**：用户指定的目标企业（如"北京北辰实业有限公司"），支持批量列表
2. **政策目录**：命题附件 74 条市、区两级政策（覆盖人才、知识产权、融资服务、人工智能、智能机器人、数据要素、数字医疗、互联网3.0、高新技术产业、商务经济、金融业、文化产业、中小企业、外商投资、青年科技人才等 15+ 领域），作为政策原文库种子数据
3. **政策权威来源**：北京市人民政府、朝阳区人民政府、北京市科委、中关村管委会、市经信局、市知识产权局等官方网站（自动更新抓取源）
4. **大模型服务**：asr 配置的大模型（昇腾 API / AtomGit，OpenAI 兼容接口）
5. **数据库**：runtime 连接的 PostgreSQL 数据库（company / tasks 表，复用现有结构）

## **1.3 核心输出**

1. **企业画像**：结构化企业画像 JSON + Markdown（`output/profiles/`）
2. **政策知识库**：三层知识库文件（`knowledge/policy-original/`、`knowledge/policy-interpretation/`、`knowledge/policy-insight/`）
3. **政策匹配结果**：企业 × 政策匹配矩阵 JSON（`output/matches/`）
4. **适配研判报告**：政策匹配报告 Markdown，含匹配依据、申报条件对标、缺口分析（`output/reports/`）
5. **政策更新流水**：每日政策抓取与研判流水（`output/pending/`）
6. **落库 SQL / 数据库记录**：company 表 upsert + tasks 表报告记录（aibuilder 可呈现）
7. **申报任务**：匹配政策的申报任务清单（task_type='policy-apply'）

## **1.4 职责边界**

本技能**不负责**以下事项：

- **不开发仓颉程序**：本次参赛只开发 Skill（SKILL.md + scripts），不做 runtime 仓颉代码修改
- **不做数据库结构变更**：复用现有 company / tasks 表结构
- **不替代人工研判**：政策储备库 → 正式库的研判确认由产业同事（人）完成，技能只做采集、匹配与建议（命题原文："产业同事研判确认后，正式汇入产业正式数据库"）
- **不抓取未授权数据**：仅使用公开、合规数据源（政府公开网站、公开工商信息）
- **不提供法律意见**：政策匹配结果仅供申报参考，不构成法律意见

# **2. 顶层设计原则**

## **2.1 原则 1：最大化复用产品体系已有能力**

| 产品能力 | 复用方式 |
|---------|---------|
| AgentSkills Runtime v0.0.27 | 技能运行环境、内置工具（web_fetch/http_request/web_search/cli_execute）、插件系统 |
| 大模型服务 | 昇腾 API（AtomGit，OpenAI 兼容），通过 `.env` 配置切换 |
| company / tasks 表 + aibuilder | 企业画像与政策报告的呈现模块 |
| WebMCP 通道 | 企业用户自然语言操作本技能（供需对接官网子系统内嵌） |
| RBAC 权限体系 + 审计日志 | 安全合规 |
| fintech-agent-hackathon 智能投研助理 SOP 模式 | 抓取→清洗→提取→生成→落库的六步流程范式 |

## **2.2 原则 2：三层知识库根除幻觉（命题核心要求）**

通用大模型在政策场景的三大困境（信息滞后 / 理解肤浅 / 逻辑失真）通过三层知识库彻底解决：

- **政策原文库**：收录市区两级最全最新政策原文，确保信息源头真实完整
- **官方解读库**：整合权威问答与解读，锚定官方口径，消除理解偏差
- **实操洞察库**：沉淀政企沟通的隐性规则与审批要点，提供落地实操指南

所有匹配结论必须引用政策原文库条目编号，无出处的匹配结果一律标记为"待核实"，不进入正式报告。

## **2.3 原则 3：全链路国产自主可控**

仓颉 Runtime + 昇腾算力（API）+ 国产数据库，满足园区数字化服务的信创要求。

## **2.4 原则 4：确定性优先**

匹配规则可解释（每条匹配给出依据与得分构成）、过程可追溯（output 目录全量持久化）、结果可复核（人工研判门禁）。

# **3. 领域术语**

**产业政策技能（beichen-policy-assistant）**
: 实现政策库—匹配库—申报库全流程的 Agent 技能（Skill），本次参赛核心开发件之一。依托 asr 插件系统可实例化为"北辰产业政策智能体"。

**三层知识库（Three-Layer Knowledge Base）**
: 政策原文库 + 官方解读库 + 实操洞察库。命题方验证的"根除 AI 幻觉"渐进式架构，本技能在 asr 内以文件型知识库 + 检索脚本实现。

**全景企业画像（Enterprise Profile）**
: 输入企业名称后自动聚合的工商、经营、舆情等全域结构化信息。

**政策库 — 匹配库 — 申报库**
: 命题定义的政策服务全流程三库：政策库（政策沉淀）→ 匹配库（企业×政策适配记录）→ 申报库（申报任务与进度）。

**政策储备库（Pending Policy Store）**
: 自动更新抓取的新政策暂存区（`output/pending/`），经人工研判后转入正式库。对应命题"产业政策储备数据库 → 产业正式数据库"机制。

**AgentSkills / SKILL.md**
: 开放标准技能格式，runtime 加载执行的技能单元。

**aibuilder**
: runtime 中的 AI Builder 模块（web-admin 前端），呈现 company 列表与 tasks 详情。

**昇腾 AI 算力底座**
: 比赛生态要求的国产算力。本作品通过 AtomGit 昇腾 API（OpenAI 兼容接口）接入。

- **公开工商/舆情数据源**：企业画像采集（合规）

# **5. 核心能力**

## **5.1 全景企业画像（Profile）**

- 输入企业名称（单个或批量）
- 多渠道公开数据聚合：工商信息（注册资本、成立日期、经营范围、资质）、经营信息（规模、行业、产品）、舆情信息（新闻正负面）
- 智能处理：信息甄别、冗余过滤、要点萃取，输出结构化画像（对标命题三层架构：数据采集层 → 智能处理层 → 落地层）
- 通过 `scripts/build_enterprise_profile.py` 实现

## **5.2 三层知识库建设（Knowledge）**

- **政策原文库**：以命题附件 74 条政策目录为种子，每条政策一个知识条目（编号、领域、层级、发布部门、政策名称、申报条件、支持方式、原文链接）
- **官方解读库**：政策问答与官方解读要点
- **实操洞察库**：申报流程要点、常见退回原因、审批偏好等实操规则
- 通过 `scripts/init_policy_kb.py` 初始化 + `knowledge/` 目录文件化管理

## **5.3 多元政策匹配（Match）**

- 双源检索：本地三层知识库 + 全网实时公开资源并行
- 语义适配研判：基于企业画像与政策申报条件的语义匹配（领域、资质、规模、阶段多维对标），非关键词匹配
- 自动筛除：无关联、已过期、企业不满足硬性条件（如注册区域、行业负面清单）的政策
- 输出匹配矩阵（政策编号、匹配度评分、匹配依据、缺口项）
- 通过 `scripts/match_policy.py` 实现

## **5.4 政策库自动更新（Auto-Update）**

- 每日定时（crontab_sched 能力 / 手动触发）从指定政府网站抓取最新产业政策
- 新政策进入储备库（`output/pending/{date}.json`），标记状态 `pending`
- 人工研判确认后执行 `commit` 动作转入正式库
- 通过 `scripts/update_policy_kb.py` 实现

## **5.5 适配报告与申报任务（Report & Apply）**

- 调用大模型（昇腾 API）生成结构化适配研判报告：匹配政策清单（按匹配度排序）、每条政策的申报条件对标表、缺口分析、申报建议
- 未配置 LLM 时降级为模板生成（保证可运行）
- 为 Top N 匹配政策创建申报任务（task_type='policy-apply'，含申报材料清单与进度字段）
- 通过 `scripts/generate_policy_report.py` + `scripts/save_to_db.py` 实现

## **5.6 结果落库与呈现（Persist & Present）**

- company 表 upsert（企业画像摘要）
- tasks 表插入匹配报告（task_type='policy-match'）与申报任务（task_type='policy-apply'）
- aibuilder 模块呈现：企业列表 → 政策匹配报告 → 申报任务

# **6. 数据约束**

## **6.1 知识库文件结构（本技能新增）**

```
knowledge/
├── policy-original/       # 政策原文库（74 条种子 + 持续更新）
│   └── {序号}-{政策名称}.md
├── policy-interpretation/ # 官方解读库
│   └── {序号}-interpretation.md
├── policy-insight/        # 实操洞察库
│   └── {领域}-insight.md
└── policy-index.json      # 政策索引（编号/领域/层级/部门/状态）
```

## **6.2 company 表（复用现有结构）**

| 字段 | 说明 |
|------|------|
| company_name | 企业名称（upsert 去重键） |
| region | 注册区域（如"北京市朝阳区"） |
| org_description | 企业画像摘要 |
| org_type | 'beichen-enterprise' |
| is_verified | false |

## **6.3 tasks 表（复用现有结构）**

| 字段 | 说明 |
|------|------|
| title | 政策适配报告 - {企业名称} / 政策申报 - {政策名称} |
| description | 报告正文（Markdown） |
| task_type | 'policy-match' / 'policy-apply' |
| task_status | 'completed'（报告）/ 'pending'（申报任务） |
| company_id | 关联 company 表 id |
| tags | ["beichen","policy-match"] / ["beichen","policy-apply"] |
| extra_data | profile_date、matched_count、policy_no |
