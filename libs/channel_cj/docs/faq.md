# 常见问题

## 基础

### 无缓冲通道和有缓冲通道有什么区别？

| 对比项 | 无缓冲通道 | 有缓冲通道 |
|--------|-----------|-----------|
| 容量 | 0 | 创建时指定 |
| 发送行为 | 必须同时有接收者就绪 | 缓冲区未满即可发送 |
| 接收行为 | 必须同时有发送者就绪 | 缓冲区非空即可接收 |
| 典型用途 | 同步、握手 | 生产者-消费者、解耦 |

### 如何选择合适的容量？

- **容量 0（无缓冲）**：需要线程间同步时使用，发送和接收必须同时就绪
- **容量 > 0（有缓冲）**：生产者和消费者速度不一致时使用，用缓冲区吸收瞬时波动
- 容量太小会导致频繁阻塞；容量太大会浪费内存。通常根据业务峰值估算：`容量 ≈ 峰值速率 × 最大容忍延迟`

## 使用

### 发送后如何知道数据已被接收？

通道本身不提供发送确认机制。如果需要确认，可以使用两个通道：

```cangjie
let dataCh = Chan<Int64>(1)
let ackCh = Chan<Bool>(1)

spawn {
    let v = dataCh.recv()  // 接收数据
    ackCh.send(true)        // 发送确认
}

dataCh.send(42)
let ack = ackCh.recv()     // 等待确认
```

### 如何实现超时？

库本身不提供超时机制。可以通过 `trySend` / `tryRecv` 实现非阻塞操作，或使用带有默认分支的 `selectOr`。

### 一个通道可以被多个发送者或接收者同时使用吗？

可以。所有通道操作都是线程安全的，支持任意数量的线程并发发送和接收。内部使用 `Mutex` 保证互斥，使用 `Condition` 实现高效的等待/唤醒。

### 关闭通道后还能读取数据吗？

可以。关闭通道后，缓冲区中剩余的数据仍然可以被接收者读取。当所有数据都读取完毕后，`recv` 会返回 `None`。

## 异常与错误

### 向已关闭的通道发送会发生什么？

会抛出 `Exception("send on closed channel")`。发送前应通过 `isClosed()` 检查通道状态。

### 重复关闭通道会发生什么？

第二次调用 `close()` 会抛出 `Exception("close of closed channel")`。

### 阻塞在通道上的线程会在关闭后被唤醒吗？

会。`close()` 会唤醒所有阻塞在该通道上的发送者和接收者。发送者会收到异常，接收者会读取剩余数据后返回 `None`。

## 性能

### channel_cj 的性能如何？

性能取决于通道类型和并发程度：
- 无缓冲通道：一次握手需要两个线程同步，开销约几微秒
- 有缓冲通道：缓冲区未满时 send/recv 只需一次 Mutex 加解锁，纳秒级完成
- 高并发场景：Mutex 的争抢会成为瓶颈，建议将通道容量设大以减少争抢

### 通道内部使用什么同步机制？

使用 `Mutex`（互斥锁）+ `Condition`（条件变量）实现。所有操作在 Mutex 保护下执行，阻塞操作通过 Condition 的 `waitUntil` 实现，不会忙等。

## 与其他语言的对比

### 与 Go 的 channel 相比有什么不同？

| 特性 | Go channel | channel_cj |
|------|-----------|-----------|
| 语法 | `ch <- v`, `<-ch` | `ch.send(v)`, `ch.recv()` |
| select | `select { case ... }` | `select([...])`, `selectOr([...], {...})` |
| 遍历 | `for v := range ch` | `ch.forEach({ v => ... })` |
| 非阻塞 | `select { default: }` | `trySend`, `tryRecv` |
| 带缓冲 | `make(chan T, N)` | `Chan<T>(N)` |
| 关闭 | `close(ch)` | `ch.close()` |
