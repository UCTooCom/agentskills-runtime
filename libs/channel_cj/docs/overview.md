# 通道模型概述

## 什么是通道？

**通道（Channel）** 是一种用于线程间通信的并发原语，借鉴自 **Go 语言** 的 channel 模型。通道允许一个线程将值发送给另一个线程，实现了 **CSP（Communicating Sequential Processes）** 通信模型的核心思想：

> **不要通过共享内存来通信，而应该通过通信来共享内存。**

## 核心概念

### 发送（send）与接收（recv）

通道的基本操作是发送和接收：

```
sender ──send(value)──▶ [ Chan<T> ] ──recv()──▶ receiver
```

- `send(value)`：将值放入通道。对于无缓冲通道，send 会阻塞直到有接收者就绪；对于有缓冲通道，send 在缓冲区未满时立即返回，否则阻塞。
- `recv()`：从通道取出一个值。recv 在没有数据时阻塞等待，通道关闭且数据耗尽时返回 `None`。

### 缓冲机制

通道分为两种模式：

| 特性 | 无缓冲通道 | 有缓冲通道 |
|------|-----------|-----------|
| 构造 | `Chan<T>()` | `Chan<T>(capacity)` |
| 容量 | 0 | 指定大小 |
| send 阻塞条件 | 必须有接收者就绪 | 缓冲区满 |
| recv 阻塞条件 | 必须有发送者就绪 | 缓冲区空 |
| 用途 | 线程同步、握手 | 生产者-消费者、解耦 |

### 线程安全

所有通道操作均由互斥锁（`Mutex`）保护，支持任意数量的线程并发读写。阻塞操作使用条件变量（`Condition`）实现高效的等待与唤醒，不存在忙等。

### 关闭

通道用完后应关闭。关闭后：
- 缓冲区的剩余数据仍可被接收者读出
- 数据耗尽后 `recv` / `tryRecv` 返回 `None`
- 阻塞的发送者收到异常
- 阻塞的接收者被唤醒并看到数据耗尽

### FIFO 顺序

Channels 保证 **FIFO（先进先出）** 顺序：
- 有缓冲通道：send 的数据按顺序排在队尾，recv 从队头取出
- 阻塞发送者：当缓冲区满时，发送者阻塞；接收者腾出空间后，会按发送者到达的顺序一一处理，保证数据的全局有序
