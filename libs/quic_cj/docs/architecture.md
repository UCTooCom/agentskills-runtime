# 架构概述

## 模块组织

```
quic_cj（根包）
├── protocol/    协议常量与类型
├── wire/        线缆格式编码/解码
├── tls/         TLS 1.3 集成
├── ack/         ACK 处理与丢包检测
├── congestion/  CUBIC + NewReno 拥塞控制
├── flow/        流量控制
├── stream/      流状态机
├── core/        连接引擎
├── sys/         UDP 套接字抽象层
├── qlog/          QUIC 事件日志（RFC 9421）
├── util/        工具函数
└── tests/       单元测试
```

## 数据流

### 出站（发送）

```
应用层 → 流 → 帧调度器 → 包打包器
                          ↓
                  TLS AEAD 加密
                          ↓
                  包头保护
                          ↓
                  UDP 套接字
```

### 入站（接收）

```
UDP 套接字 → 包解包器 → 包头去保护
                          ↓
                  TLS AEAD 解密
                          ↓
                  帧解析器 → 流
                          ↓
                  应用层
```

## 关键设计决策

### 1. Option 返回值
可能失败或无可达数据的操作返回 `Option<T>`（`Some(value)` / `None`），调用方使用 `if (let Some(v) <- f())` 处理：

```cangjie
if (let Some(stream) <- conn.openStream()) {
    // 成功分支
} else {
    // 失败分支
}
```

### 2. 枚举比较
仓颉不支持枚举的 `==` 比较。所有枚举比较均使用 `match` 表达式：

```cangjie
let isInitial = match (state) {
    case ConnectionState.Initial => true
    case _ => false
}
```

### 3. 静态库输出
库构建为静态库（`output-type = "static"`），以便链接到仓颉应用程序。

### 4. 数组限制
泛型 `Array<T>` 不支持下标赋值。项目使用具体类型数组和手动元素拷贝。

## 连接状态机

```
初始 ──→ 握手 ──→ 已建立 ──→ 关闭中 ──→ 已关闭
   │                          │
   └──────────────────────────┘
         （空闲超时）
```

状态说明：
- **初始：** 握手开始之前
- **握手：** TLS 1.3 握手进行中
- **已建立：** 连接活跃，拥有 1-RTT 密钥
- **关闭中：** 等待关闭确认
- **已关闭：** 连接完全终止
