# App Coder 技能（纯技能形态）

## 概述

面向 **微信小程序 / 移动端原生应用** 的编码技能。由**主 agent 加载后按 SOP 自行执行**，
不派生任何编码子 agent（SDD 六步 code 步的 app 语言分支即走这里）。

**触发场景**：小程序页面/组件/云函数调用、原生 App 模块、跨端适配、端上接口对接。

## 与 cangjie-coder 同构的四步工作流

```
1. 查依据   → 官方文档（小程序 / 目标端 SDK）+ 工程内既有实现
2. 检索     → 在目标工程检索可复制的既有正确代码（页面骨架、请求封装、登录态处理）
3. 编辑适配 → 复制 → 最小适配，禁止从零凭空生成
4. 自检     → 配置/路径/约定自查（不执行构建与真机调试，由人工完成）
```

## 铁律（违反即视为返工）

1. **先查依据再写代码**：端上 API、生命周期、配置文件字段必须来自官方文档或工程内既有用法，
   **禁止**凭 Web 端经验臆造小程序/原生 API（两端同名 API 行为差异常常是坑的来源）。
2. **复制粘贴 + 二次编辑**：先找同类型既有页面/模块照结构写。
3. **缺口必须显式标注**：查不到确定依据时写明"缺什么、需人工确认什么"，禁止静默猜写。
4. **不执行构建与真机调试**：编译、预览、上传由人工在开发者工具完成；AI 只产出代码与建议。
5. **改动只落在目标工程目录内**。

## 端上特有红线

- **HTTPS 即 WSS**：小程序/端上用 wss 连后端，不要把 ws 与 https 混配。
- 登录态：端上只持 token，不落明文凭证；请求统一带 `Authorization: Bearer <token>`。
- 域名白名单：新增接口域名必须同步到小程序后台配置，代码里改了不算完。
- 路径与分包：新增页面必须同步 `app.json`（或等价清单）的 pages/subpackages，
  否则编译通过但页面打不开。

## 回传契约（code 步要求）

```json
{
  "changed_files": ["miniprogram/pages/..."],
  "verify_passed": true,
  "language": "app",
  "skill_used": "app-coder",
  "gaps": ["某端 API 在低版本基础库不支持，需人工确认最低版本"]
}
```

`verify_passed=false` 时必须附失败项清单；走了过渡期路由（`frontend-dev`）必须在
`skill_used` 里写明，禁止静默 fallback。
