## 3. 集成契约汇总（全局接口表）

表格：**编号 | 接口/事件 | 提供方 | 消费方 | 方向(单向/双向) | 路径或标识 | 请求→响应形态 | 数据契约(表.字段) | 契约版本 | 冻结日 | 状态**

- 本表是跨子系统组合集成的**唯一**接口账本；新增/变更一律按 SKILL.md 铁律 15：
  「先改契约 → 再改实现」，禁止单边先改。
- 方向**必须单向无环**；出现双向先判为拆得不对，回 §4 找边界。
- 状态：`已冻结` / `演进中(minor)` / `破坏性变更待双侧同轮` / `已废弃`

## 4. 子系统依赖 DAG

```mermaid
graph LR
  A[{sub-A}] --> B[{sub-B}]
```

- 边方向 = 依赖方向（上游 → 下游）；节点 = 子系统 ID。
- **无回边自检**：本 DAG 不允许出现任何回边；自检办法：按拓扑序编号，编号必须递增。
- 说明：无依赖关系的子系统可**并行**推进；有依赖的按拓扑序串行；
  上游进 `code` 步前，其上游必须已达 `test`（下游闸口才会放行）。

## 5. 组合集成验收基线

> **各子系统不得只跑自己的单测就报 done** —— L2 是硬档位，不是加分项。

| 档位 | 谁执行 | 在什么样的合并态上跑 | 通过判据 |
|---|---|---|---|
| **L1** 单子系统自测 | 子系统自身 test 步 | 本子系统 | 自身 spec 每条验收条件通过；P0 清零 |
| **L2** 跨子系统集成 | 下游子系统 test 步 | 与**已 done 的上游**合并后的运行态 | 契约 §6 冒烟用例全绿；跨边界数据一致性校验通过 |
| **L3** 主工程端到端 | 主工程 test 步 / 总装验收 | 全量已 done 子系统在宿主上跑起 | §5.1 端到端用例全绿 + 权限/行级可见范围复核 |

- **L2 最小冒烟清单**（不少于 3 条主干 + 1 条异常）：
  1. （跨 {A}→{B} 主流程）
  2. （跨 {C}→{D} 主流程）
  3. （异常：跨边界权限不足 / 数据不存在 / 上游超时）
- **环境/数据前置**：宿主已起 ✓/✗ ｜ DB 迁移已执行 ✓/✗ ｜ 缺什么 → 【人工】
- 任何子系统报 done 时若 L2 未跑，主工程闸口**不予确认**（这是硬闸，不是建议）。

## 6. 变更影响面

表格：**日期 | 变更子系统 | 变更类型(内部实现/契约 minor/契约 major) | 影响子系统 | 是否需回归 L2 | 关联子系统任务号 | 登记人**

- `契约 major` 的行必须同时满足：双侧同轮完成 + §3 状态改为「待双侧同轮」+ 关闭后回写本行。
- 未登记就改代码 = 契约漂移，在子系统 `test-report.md` 缺陷分级里**升 P0**。

## 7. 风险与已知偏差

表格：**类型 | 描述 | 影响 | 缓解 | 归属子系统**

- 「已知偏差」必须具体到文件与条目，禁止写"实现与文档略有出入"。
