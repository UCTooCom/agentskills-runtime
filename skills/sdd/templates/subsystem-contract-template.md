## 1. 本子系统提供什么（能力清单）

表格：**编号 | 类型 | 路径或标识 | 方法 | 请求形态 | 响应形态 | 错误约定 | 幂等性 | 备注**

- 类型口径（选一种填，别含糊）：
  | 类型 | 适用 | 备注 |
  |---|---|---|
  | HTTP | 对外/对上首选 | 路径 `/api/v1/uctoo/...`；列表键名 = 表名 + `s`，分页/筛选/排序按 `uctoo-v4-api-specification` |
  | 库表 | 数据面 | 只允许暴露 §2 认可的字段，下游**禁止**直连本子系统私有表 |
  | L3 插件跨轨 | 跨 sync / process 轨 | 走 `host.db` / `host.mcp` / `host.event` 六类 RPC，不走裸文件 |
  | 进程内调用 | 同进程内 | 必须在本文注明求值方式（构造注入 / DI），便于下游测试替身 |
- **错误约定**：统一错误响应结构（复用 uctoo 既有约定），跨子系统**不得自造错误码**；
  错误码冲突时以主工程 §3 汇总表裁决。
- **幂等性**：写类接口必须声明幂等键（如 `request_id`），下游重试才有依据。

## 2. 数据契约

表格：**表 | 本子系统读/写 | 对外暴露字段 | 对外屏蔽字段 | 行级权限 | 软删约束**

- 行级权限口径：沿用 `user-permission-system.md` / `row-level-permission-system.md`；
  `creator` / `owner_user_id` 判定归本子系统，**下游不得自行解释**。
- 软删：所有对外查询必须显式带 `deleted_at IS NULL` 语义，下游不得自己拼删除过滤。
- 约束红线（**铁律 9**）：本子系统可用的新表 ≤2、既有表新增列 ≤2 额度独立计；
  额度不够就升级人工闸口，禁止绕。

## 3. 依赖方向

- **我依赖的上游**（有限名单，只允许这几条，禁止反向）：
  1. `{上游子系统ID} v{v}` —— 取什么能力，契约版本对齐到哪版
- **我不依赖谁**：明确保留位。典型写法「不依赖 `{X}` 的实现细节，只依赖其 §1 的 N 号接口」。
  > 写成"不依赖"是为了给下游留口子：将来真要依赖，必须回本文改依赖方向并过闸口，
  > 而不是在实现里偷偷 import 过去（那就是依赖漂移，按 P0 计）。
- **禁止成环**：本子系统与任一上游若出现双向依赖，合并回去重新切边界（见 SKILL.md 颗粒度红线）。

## 4. 我明确不提供什么

表格：**能力 | 归属子系统 | 原因/备注**

- 作用：避免两个子系统抢同一件事，也避免下游误以为本子系统有某能力而绕路直连。
- 归属子系统必须是**已登记**的子系统 ID；找不到归属的 → 这是拆分漏项，回主工程补拆分或加一条 §1 接口。

## 5. 契约兼容与演进

| 档位 | 判定 | 怎么处理 |
|---|---|---|
| 内部实现改动 | 不动 §1/§2/§3 | 本文不动；在子系统 tasks.md 修订记录留痕即可 |
| 向后兼容（minor） | 只增接口/只增可选字段，不改既有语义 | 改本文 + 主工程 §3 汇总；下游不必同步改 |
| 破坏性（major） | 改路径/改字段语义/删接口/改权限口径 | **必须双侧同轮**：提供方与全量消费方在同一轮 code 里改完；主工程 SPECS_INDEX §6 登记；单侧先改 = P0 缺陷 |

- 演进一律「**先改契约 → 再改实现**」，顺序反了按铁律 15 打回。
- 契约冻结后到实现完成之间的任何偏差，在子系统 `test-report.md` 里必须归因到具体契约条目，禁止笼统写"实现与文档略有差异"。

## 6. 集成验收（本子系统对下游的交付承诺）

表格：**编号 | 冒烟用例 | 验证方式 | 依赖的上游 | 通过判据**

- 至少覆盖：1 条跨子系统主干流程 + 1 条异常/边界（权限不足、数据不存在、上游超时）。
- 归属档位：本文 §6 用例由**本子系统 test 步**产出与执行（L1 + L2）；
  主工程端到端（L3）在主工程 test 步执行，不在这里重复。
- **上游就位前提**：写明"依赖 `{X}` 处于 done 且不晚于本文冻结日"，避免下游在半成品上游上跑冒烟拿假失败。
