# 测试验收报告模板（test-report.md）

> 由**测试验收子 agent** 产出。依据：`spec.md`（验收标准 / EARS）、`design.md`（技术方案）、`tasks.md`（任务与产出物）。
> 报告须覆盖：产出物与 SDD 文档的一致性、完成度、缺陷、完善意见。
> 本模板由本仓库既有验收类产物（如 long-running-task 的 `vN_fix_report.md`、各 `tasks.md` 验收检查清单）反演而来——CodeArts Agent 未提供标准测试验收模板。

## 文档信息
- 被测对象 / 版本 / 测试轮次 / 测试日期 / 测试人（子 agent）

## 一、测试概述
- 测试目标、范围、策略（单元测试 / 集成测试 / 端到端 / 文档一致性核查）。

## 二、测试依据
- `spec.md` 验收标准条目（列出被验证的编号与原文）。
- `design.md` 关键方案约束（复用项、接口契约、DFX 实现方式）。
- `tasks.md` 任务清单与对应产出物路径。

## 三、测试环境与工具
- 运行环境、依赖版本、测试工具（如 pytest、人工 `cjpm build` 回传日志等）、数据准备与前置条件。

## 四、测试执行与结果
表格：**用例ID | 所属需求 | 测试项 | 前置 | 步骤 | 预期 | 实际 | 结果(P/F/阻塞)**
- 统计：总数 / 通过 / 失败 / 阻塞、通过率。

## 五、与 SDD 文档的一致性核查
- **实现 vs spec**：功能需求逐条核对（满足 / 偏离 / 缺失）。
- **实现 vs design**：是否按方案落地、复用项是否被无意重写。
- **文档 vs 代码**：spec/design/tasks 是否仍与实现一致（漂移检测，标出过期条目）。

## 六、完成度评估
- 需求完成度百分比（按功能需求、DFX 分别统计）。
- 哪些需求完全闭环、哪些部分完成、哪些尚未启动。

## 七、缺陷清单（分级）
表格：**缺陷ID | 级别(P0/P1/P2) | 关联需求 | 现象 | 根因 | 建议修复 | 状态**
- P0 阻断交付；P1 严重影响；P2 一般/体验。

## 八、完善意见
- 架构 / 性能 / 安全 / 可维护性改进建议（分优先级）。
- 文档（spec/design/tasks）补充与订正建议。

## 九、验收结论
- 是否通过验收：**通过 / 有条件通过 / 不通过**。
- 遗留风险与后续行动项（含负责人与时限建议）。

## 十、附录
- 日志、截图、复现脚本、相关 PR/Commit 索引。
