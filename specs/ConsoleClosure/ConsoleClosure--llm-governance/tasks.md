## 开发规范（全任务强制遵守）
- **语言与工具绑定**：本子系统全部为前端任务 → `web-coder`（code 步由主 agent 加载，非子 agent 派生）。无仓颉任务，不触碰 runtime `src/app/` 与 `*.cj`。
- **二次开发底座优先（铁律 14）**：前端复用 web-admin 既有 `src/store/models/uctoo/*` Model 层与 `src/router/guard/menu.ts` 动态注入机制；不另起取数框架，不推倒重写既有页。
- **大工程拆分边界（铁律 15）**：
  1. 已读 `SPECS_INDEX.md`：S3 ID、feature_name=`ConsoleClosure--llm-governance`、无上游依赖、验收 L1+L2+L3。
  2. 每条任务标注「本子系统负责」与「不碰（移交/调用上游契约接口）」；跨子系统一律落成"调用上游契约接口"或"等下游消费"。
  3. 契约先行：C-013 / C-024 已冻结，只消费不改；变更须走 `SPECS_INDEX.md` §6 登记。
- **编译约束**：AI 不运行 `cjpm build`；编译/类型检查/lint 由人工执行并回传。
- **复用原则**：五张治理表与 C-013/C-024 端点全部复用，零新增表/列（铁律 9 / R4）。
- **权限硬约束（R6/M-1）**：新界面入口必须 `permissions` + `role_has_permission` 登记 + `loaddbinfo`，否则 403 / 看不到入口。
- **命名/注释/错误处理**：遵循 web-admin 既有范式；接口失败按 `接口路径 + 服务端 reason` 输出控制台（M-2）。

## 任务详细说明（按编号展开）

### T-01 规范对齐与冻结契约/复用清单确认
- **目标**：确认本子系统只消费既有/冻结接口，零新增表/列；不越界（spec §1.4）。
- **输入**：spec.md / design.md §1.2/§4/§5。
- **步骤**：
  1. 复核 C-013、C-024 已冻结，列出只读消费清单（design §5.1）；
  2. 复核五表字段齐备，确认无新增表/列诉求（design §4.1）；
  3. 记录不碰边界：通道 CRUD 本身、服务端计费链路、Electron 壳、api_key 加密存储。
- **产出物**：无代码；核对笔记（可入 PR 描述）。
- **验收**：冻结契约清单与复用表清单与设计 §4/§5 一致；无越界项。
- **风险**：误判"需要新接口"→ 回 spec 确认后改为本地计算或标注不支持。

### T-02 新增 5 治理界面目录骨架 + 共享组件
- **目标**：在 `views/ai/llm_gov/` 下建 5 个同级界面骨架，并建 `components/llm_gov/` 共享组件；不重建/不覆盖既有 `model_channel`/`token_dashboard`/`billing_report` 页。
- **输入**：T-01 清单；web-admin 既有 `src/views/ai/*` 范式。
- **步骤**：
  1. 建 `views/ai/llm_gov/{pricing,quota,usage,health,audit}/index.vue` 空壳；
  2. 建 `components/llm_gov/{ScopeBadge,QuotaAlertBar,ChannelDeepLink}.vue`；
  3. 字段名统一走 Model 层映射，不硬编码（M-3）。
- **产出物**：上述 `.vue` 骨架文件。
- **验收**：5 界面与 3 共享组件创建成功；路径不占用 `model_channel/` `token_dashboard/` `billing_report/`（C-3）。
- **风险**：误覆盖既有页 → 严格新建同级目录，禁止改既有文件内部结构。

### T-03 菜单与权限登记（5 入口）
- **边界**：本子系统负责「登记」动作（产出 SQL 种子 + 触发 loaddbinfo）；**不碰** C-024 契约结构本身（已冻结）。
- **目标**：5 个界面入口进后端菜单树 + RBAC 双层，否则用户看不到入口或 403（R2/R6/M-1）。
- **输入**：design §7.2/§9.1；`SPECS_INDEX.md` §3 C-024、§5.3。
- **步骤**：
  1. 为每个界面生成菜单节点（`permissions` 表，`menu_type` 非空、`type=1`、`deleted_at IS NULL`，参照隐藏菜单机制备忘）；
  2. 生成 `permissions` 权限项 + `role_has_permission` 授权（对超管因通配权 `*` 走全量分支，仍须登记以保证非超管可见）；
  3. 写幂等种子 SQL 到 `sql/incremental/`（INSERT ... WHERE NOT EXISTS，因 i18 表无唯一约束，参照同款幂等写法）；
  4. 执行后跑 `loaddbinfo`（菜单取数依赖 db_info）。
- **产出物**：`sql/incremental/20261030_llm_gov_menu_permissions.sql`（数据种子，**非 schema DDL**）+ loaddbinfo 执行记录。
- **验收**：以非超管账号登录，5 入口可见且可进入（非 403）；超管同样可见。
- **风险**：漏登记 → 「做了但看不到」（R2）；超管分支误导 → 须用非超管账号验证（R6 备注）。

### T-04 C1 模型定价维护界面
- **边界**：本子系统负责前端；**不碰** 服务端计费链路（`BillingEventHandler` 等）；写走 `model_pricing/{add,edit}` 既有壳。
- **目标**：倒序展示 + 生效中标记 + 字段校验 + 快照免责标注（spec §5.1）。
- **输入**：spec §5.1/§6.1；design §3.1。
- **步骤**：
  1. 调 `GET /model_pricing/:limit/:page`，按 `effective_from` 倒序，`is_active` 且在区间内标「生效中」；
  2. 字段校验：单价 `>=0`、币种非空、`effective_to` 晚于 `effective_from`（否则字段级拦截）；
  3. 新增/编辑走 `POST /model_pricing/{add,edit}`，失败保留表单 + 展示 `reason`（R-2）；
  4. 显著标注「历史用量金额取自当次成交快照，修改本页不会重算历史费用」，不提供重算入口（规则 4）；
  5. T-5 枚举：自由输入 `provider/model`，服务端现存口径校验。
- **产出物**：`LlmGovPricingView.vue`。
- **验收**：倒序/生效中正确；非法输入被拦截；快照免责标注可见；无重算入口。
- **风险**：并发后写覆盖（无乐观锁）→ 仅提示「后写覆盖」，不做 Diff。

### T-05 C2 用量配额治理界面
- **边界**：本子系统负责前端；**不碰** `QuotaCheckHandler` 调用点（T-1 倾向不补，如实展示现状）；告警本地计算，不调服务端告警接口。
- **目标**：作用域口径 + 阈值比值告警 + 硬/软限区分 + 周期前缀提示 + 本地告警（spec §5.2）。
- **输入**：spec §5.2/§6.2；design §3.1/§3.2。
- **步骤**：
  1. `target_type=global` 自动置 `target_id=*` 且禁手写（规则 1）；
  2. `alert_threshold` 校验 `[0,1]` 为比值，超界拦截并提示「比例非百分比」；达阈值渲染告警色 + 百分比读数（规则 2）；
  3. `is_hard_limit` 区分「硬限-已拦截」/「软限-放行中」，绝不渲染软限为阻断态（R-3）；
  4. 非 `daily_/weekly_/monthly_` 前缀提示「不会被自动重置」（规则 4）；
  5. 本地计算告警态（服务端仅 `LogUtils.warn` 无出口）；T-1 未确认前悬停提示「`quota_used` 当前不会被调用链路自动累加，请以实际值为准」（规则 5）。
- **产出物**：`LlmGovQuotaView.vue` + `QuotaAlertBar.vue`。
- **验收**：阈值/硬软限/周期提示全部正确；无「强制放行」按钮；无「用量自动累计」宣称。
- **风险**：`quota_limit=0` 除零 → 提交前拦截（规则异常 1）；脏数据进度条封顶标注（异常 2）。

### T-06 C3 用量明细查询 + 汇总视图
- **边界**：本子系统负责前端；**不碰** C-013 契约（冻结）；汇总接 `llm-usage-stats/summary`（M6 处理）。
- **目标**：五维筛选 + 只读 + 快照优先 + 口径差异标注 + 汇总视图（spec §5.3）。
- **输入**：spec §5.3/§6.3；design §3.1/§8.2（M6）。
- **步骤**：
  1. 调 `GET /llm_usage_logs/:limit/:page`（**真实分页**，server 尊重入参，与 C-013 隔离）；
  2. 五维筛选：Agent/模型/供应商/时间/是否出错；`error_message` 非空标失败样式（规则 2）；
  3. 金额直接展示 `cost_amount`/`cost_currency`，不用 `model_pricing` 现值反算（规则 3）；
  4. 切「汇总视图」调 `GET /llm-usage-stats/summary`（C-013 冻结），`ScopeBadge` 常驻「最近 10000 条」标注，**禁止前端二次全量聚合**（P-2/M6）；
  5. 页脚小计与 C-013 聚合不一致时标注口径差异（规则 4）；空态列筛选条件 + 清空按钮（异常 1）；显式刷新按钮应对异步落盘延迟（异常 2）。
- **产出物**：`LlmGovUsageView.vue` + `ScopeBadge.vue`。
- **验收**：筛选/只读/快照优先正确；汇总视图带常驻范围标注且无前端重算；分页真实生效。
- **风险**：误把 C-013 当可分页 → 严格只渲染返回聚合 + 标注，不传 limit。

### T-07 C4 通道健康历史界面
- **边界**：本子系统负责前端；**不碰** 通道 CRUD；深链跳 `model_channel/index.vue`（复用既有页，不另建）。
- **目标**：list 映射 + 只增不删 + 失败/慢点分类 + 深链跳（spec §5.4）。
- **输入**：spec §5.4/§6.4；design §3.1/§3.2。
- **步骤**：
  1. 先 `GET /llm_channel/list` 取 `channel_id→code` 映射，以 `code` 作图例；
  2. 调 `GET /llm_channel_health/:limit/:page`，只读，禁增删改（该表无 `deleted_at`，R-1）；
  3. `ok=false` 展示 `error_code`/`error_message` 原文；`ok=true` 且 `latency_ms>2×P95` 标慢点（规则 3）；
  4. 点击异常点深链跳 `model_channel/index.vue` 定位通道（规则 4）；`channel_id` 无对应时以原值兜底 + 灰图例 + 禁用跳转（异常 2）；
  5. 时间窗默认 ≤30 天、点位 ≤500，超限提示缩小（P-3）。
- **产出物**：`LlmGovHealthView.vue` + `ChannelDeepLink.vue`。
- **验收**：code 图例正确；失败/慢点分类正确；深链跳转生效；超点位提示不静默截断。
- **风险**：静默截断 → 前端预校验时间窗/点位上限并拦截。

### T-08 C5 通道审计追溯界面
- **边界**：本子系统负责前端；**不碰** 审计写（由 runtime 在配置变更时落盘）。
- **目标**：四维检索 + before/after Diff + 默认折叠 + 来源可见（spec §5.5）。
- **输入**：spec §5.5/§6.5；design §3.1。
- **步骤**：
  1. 四维检索：operator/action/channel/时间，按 `created_at` 倒序；
  2. `channel_id` 空显示「—」并支持不按通道筛选（规则 3）；
  3. 展开记录并排 Diff `before`/`after`，默认折叠（规则 2，S-3）；超长折叠 + 全文查看不截断（异常 1）；
  4. `operator` 空渲染「系统」（异常 2）；`source` 列必展示（规则 4）。
- **产出物**：`LlmGovAuditView.vue`。
- **验收**：四维检索/Diff/折叠/来源可见全部正确；无删除入口（R-1）。
- **风险**：敏感片段泄露 → 默认折叠 + 仅审计员可展开（S-3）。

### T-09 C-013 冻结聚合/报表透传（含 M6）
- **边界**：本子系统负责前端透传渲染；**不碰** C-013 契约（冻结，路径/方法/入参/返回不改）。
- **目标**：summary/by-agent/by-model/daily/monthly 渲染 + export-csv 透传 + 常驻范围标注（spec §4.1 P-2/P-4、§9 M6）。
- **输入**：spec §4.1/§9（M6）；design §5.1/§8.2。
- **步骤**：
  1. 消费 6 个 C-013 端点，直接渲染返回结果；by-agent/by-model 排名直接消费 `ranking[]`；
  2. 全部接 C-013 视图常驻 `ScopeBadge`「统计范围：最近 10000 条用量明细」（P-2/M6）；
  3. `export-csv` 触发下载、透传服务端字节流，前端零计算（P-4）；
  4. 禁止前端二次全量聚合（design §8.2 策略 2）。
- **产出物**：报表透传视图片段（挂 T-06 汇总视图 + 独立日报/月报入口）+ 复用 `ScopeBadge.vue`。
- **验收**：6 端点消费成功；范围标注常驻；CSV 透传无误；无前端重算。
- **风险**：误以为 C-013 可传 limit → 严格只读、标注入参被忽略。

### T-10 G6 PC 多通道入口（最小口径，按 T-4）
- **边界**：本子系统负责「可被 iframe 直达」的 Web 界面 + 菜单/权限登记；**不碰** Electron 集成壳（归 S6 / C-023）；**不改动** `SettingsView.vue` 单条 AI 配置逻辑（T-4 未确认前）。
- **目标**：交付同源 token 下可 iframe 渲染的治理界面，复用 Web 界面不写第二套 Vue（spec §5.6）。
- **输入**：spec §5.6；design §2.3/§9.1。
- **步骤**：
  1. 确认 5 个治理界面在同源/同 token 下可被 `HomeView.vue` iframe 直达（复用 T-02/T-03 产物）；
  2. 不新增 pc-client Vue 页；不修改 `SettingsView.vue`（`electronAPI.config.set('ai', ...)` 保持原样）；
  3. 若 T-4 后续确认归属变更，本子系统仅保留 iframe 可达交付物，其余回退 S6。

- **验收**：桌面壳经 C-023 深链打开治理界面，同源渲染且保留桌面侧边栏；无双份实现（R7）。
- **风险**：在 pc-client 重写第二套页 → 严禁（R7）；归属变更 → 按 T-4 回退 S6。

### T-11 安全与合规收口（S-1/S-3/S-4/C-4）
- **边界**：本子系统负责前端合规；**不碰** runtime `api_key` 加密存储（复用 `LlmChannelPO.api_key_set`）。
- **目标**：密钥不渲染、审计折叠、走服务端路径、版本位「待确认」（spec §4.3/§4.5）。
- **输入**：spec §4.3（S-1~S-4）/§4.5（C-4）；design §7.3。
- **步骤**：
  1. 全界面禁渲染/日志/导出 `api_key`，仅「已配置/未配置」徽标（S-1）；
  2. 审计 before/after 默认折叠（S-3，与 T-08 协同）；
  3. 写操作均走既有 CRUD 壳/Service，禁直连写表（S-4）；
  4. 所有版本展示位（导出文件名、快照版本标记、页脚）渲染「待用户确认」（C-4，T-3）。
- **产出物**：各界面合规改造（合并入 T-04~T-08/T-09 文件或独立收口组件）。
- **验收**：密钥零泄露；版本位无推测值；写操作均经服务端路径。
- **风险**：版本位误写推测值 → 一律「待用户确认」（T-3）。

### T-12 性能与可靠性收口（P-1/P-3/P-4/R-1/R-3）
- **边界**：本子系统负责前端性能/可靠性；M6 已在 T-06/T-09 消化。
- **目标**：首屏 ≤3s、健康点位上限、CSV 透传、禁删禁放行（spec §4.1/§4.2）。
- **输入**：spec §4.1（P-1/P-3/P-4）/§4.2（R-1/R-3）；design §8.1/§8.2。
- **步骤**：
  1. 三列表默认 20 条/页、单页 ≤200 条分页（P-1）；
  2. 健康页时间窗 ≤30 天、点位 ≤500 前端预校验（P-3，与 T-07 协同）；
  3. CSV 透传零计算（P-4，与 T-09 协同）；
  4. 健康/审计页禁删除入口（R-1）；任何界面禁「强制放行」按钮、禁软限渲染阻断态（R-3）。
- **产出物**：性能/可靠性收口（合并入相关界面）。
- **验收**：首屏计时抽检 ≤3s；超点位拦截；无删除/放行入口。
- **风险**：静默截断 → 前端拦截并提示。

### T-13 自测与 L1 验收 + L2 跨边界冒烟准备
- **边界**：本子系统负责 L1 自测；L2 由下游 S6 在合并态跑（本子系统提供冒烟用例清单）。
- **目标**：spec 每条验收条件通过；准备跨边界冒烟（≥3 主干 +1 异常）。
- **输入**：全量 spec/design/tasks。
- **步骤**：
  1. 逐条核对 spec C1-C6 验收条件是否实现；
  2. 准备 L2 冒烟用例：① S3 治理界面在 S6 iframe 中同源渲染（主干）；② 非超管账号见 5 入口且可进（主干，依赖 T-03）；③ 明细页分页真实生效 + C-013 范围标注常驻（主干）；④ 异常：低权限用户访问仅超管可见的定价写接口返回 403（异常）；

- **产出物**：自测清单 + L2 冒烟用例清单（供 S6 消费）。
- **验收**：C1-C6 自测全绿；冒烟用例清单完整；待确认项已文档化。
- **风险**：只跑 L1 报 done → 违反 L2 硬档位，主工程闸口不确认。
