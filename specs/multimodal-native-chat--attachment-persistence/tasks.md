## 开发规范（全任务强制遵守）

- **语言与工具绑定**：仓颉 → `cangjie-coder`；管理界面 → `crudweb` 生成物上最小适配。
- **大工程拆分态（铁律 15）**：本子系统 ID = `attachment-persistence`；上游 = `host-attach-core` v1；验收档位 L1+L2+L3；跨子系统接口改动成对成条（事件发布侧 T-HAC-11 ↔ 本侧消费）。
- **铁律 9（复用优先）**：本子系统拟给 `agent_messages` / `messages` 各加一个 `attachments` JSON 列，**必须在 design 步写明复用不成立理由**（已在 contract §2 给出），未论证不得开工。
- **二次开发底座优先**：
  1. `loaddbinfo`（命令行模式有未修问题 → 退到 Web 端「数据库管理 → 加载数据库信息」）→ `crudgen`（宿主公共基础设施）→ `crudweb`（界面）。
  2. DDL 放 `sql/incremental/`，幂等、禁 DROP，执行后必跑 `loaddbinfo`。
  3. 新增宿主路由必补 `permissions` + `role_has_permission` 登记，否则 403。
- **编译约束**：AI 不运行 `cjpm build`；SQL 执行与 `loaddbinfo` 由人工执行。

## 任务详细说明（按编号展开）

### T-AP-01 契约确认
- **目标**：`AttachmentParsed` 事件结构与宿主侧发布点一致。
- **验收**：字段清单、幂等键（`messageId` + 附件序号）、失败语义书面确认。

### T-AP-02 design 步：复用论证与加列方案
- **目标**：过铁律 9 的闸。
- **步骤**：① 明确写「为何不能复用既有列」「为何没有 payload 类容器可复用」；② 论证加列优于新建表；③ 定 JSON 结构 schema。
- **验收**：论证文本进入 `design.md`，主工程闸口确认。
- **风险**：未论证就加列 = 违反铁律 9，打回。

### T-AP-03 增量 DDL
- **步骤**：① 参照 `sql/uctooDB.sql` 既有类型抄写；② 落 `sql/incremental/<YYYYMMDD>_attachment_attachments.sql`；③ 幂等（`IF NOT EXISTS` 同类写法）、禁 DROP。
- **验收**：可重复执行不报错。

### T-AP-04 执行 DDL + `loaddbinfo`
- **执行人**：人工。
- **验收**：`db_info` 中可见新列。

### T-AP-05 五层代码补齐
- **步骤**：优先 `crudgen` 生成宿主公共基础设施；手动补则须严格参照生成逻辑把 PO/DAO/Service/Controller/Route **所有位置补全**，不得只改一半。
- **验收**：编译通过（人工回传）；列表/详情接口可调用。

### T-AP-06 权限登记
- **验收**：新增路由在 `permissions` 有节点、`role_has_permission` 已授权；否则 403。

### T-AP-07 事件订阅与落库
- **目标**：SC-31 / SC-32。
- **步骤**：① 订阅 `AttachmentParsed`；② 按幂等键去重；③ 写元数据与解析摘要；④ 字段按 §6.1 全量落。
- **验收**：重复事件不产生重复记录。

### T-AP-08 落库失败不阻塞主链路
- **目标**：SC-34。
- **验收**：DB 不可用时聊天仍正常返回，error 日志有记录。

### T-AP-09 管理界面
- **步骤**：`crudweb` 生成后最小适配（列表筛选：会话/时间/格式/状态/解析器）。
- **验收**：界面可查，权限过滤生效。

### T-AP-10 会话回放
- **验收**：SC-33。

### T-AP-11 禁止落大 base64 防护
- **步骤**：① 写入层显式丢弃 `rawContent`；② 加自检（扫描/断言）确认列内不含长 base64。
- **验收**：自检脚本可跑且通过。

### T-AP-12 L1 自测 / T-AP-13 L2 冒烟
- **验收**：SC-31~SC-35 全绿。
